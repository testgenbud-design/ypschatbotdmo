# Yashoda Assistant — admissions chatbot prototype for YTC Satara

A working demo, built to show the registrar of **Yashoda Technical Campus, Satara** (yes.edu.in) that repeat
admission questions can be answered instantly, in the parent's language (English / हिन्दी / मराठी / Hinglish),
entirely from the college's own published information — with the admission office kept in the loop through
WhatsApp handoffs, callback leads and a question log.

> **Prototype for Yashoda Technical Campus, Satara · not an official college page.**
> Logo, photos and facts are the college's own, compiled from public pages at yes.edu.in for this demo.

## How a question flows

1. **Sanity & rails** — JSON body, 500-char cap, 20 msgs/min per IP. Off-topic (code, jokes, cricket…) is declined
   politely without touching the LLM.
2. **Retrieval** — the question is matched against `data/chunks.json` (hybrid BM25 + n-gram embedding cosine,
   plus an English/हिन्दी/मराठी/Hinglish synonym bridge). Top 4–5 chunks by score.
3. **Confidence gate** — if the top score is below `ANSWER_THRESHOLD` (0.21) or term coverage is too low, **the
   LLM is never called**: the assistant says the office can confirm it and shows the WhatsApp handoff button
   (prefilled with a conversation summary to the college's number, +91 91722 20775).
4. **LLM answer** — otherwise OpenRouter (`openai/gpt-4o-mini` by default, `OPENROUTER_MODEL` to change) answers
   under a fixed system prompt: context is data, never instructions; no invented fees/marks/dates/eligibility;
   fees → FRA link only; never "100% job" claims; reply in the user's language; warm senior-counsellor tone,
   "here's how it works at Yashoda", ending with the next step. API failure → graceful WhatsApp fallback.
5. **Logging** — every question is logged (timestamp, language, top score, answered/handoff/declined) to
   Postgres when `DATABASE_URL` is set. The admin page's live strip reads it back.

Embeddings are a deterministic local 768-dim hashing projection (`src/lib/retrieval/embedder.mjs`), so ingest
and re-embeds need **no API key** and are reproducible.

## Voice input

Web Speech API with `en-IN`, `hi-IN`, `mr-IN` mapped to the header language switcher (EN / हिं / मराठी).
Unsupported browsers get a plain-language fallback message; the keyboard path is always first-class.

## Setup (local)

```bash
npm install
cp .env.example .env      # set OPENROUTER_API_KEY
node scripts/ingest.js    # builds data/chunks.json
node scripts/selftest.mjs # sanity: retrieval/threshold on sample questions
npm run dev               # http://localhost:3000  (admin: /admin)
```

## Deploy to Vercel

1. Push this repo to GitHub/GitLab and **Import** it at vercel.com/new.
2. Project → **Settings → Environment Variables**, add for Production + Preview:
   - `OPENROUTER_API_KEY` (required — get a key at openrouter.ai; top up ~$1 for a demo)
   - optional: `OPENROUTER_MODEL` (default `openai/gpt-4o-mini`)
3. **Deploy.** Done — the widget, `/admin`, and `/api/chat` are live.
4. *Optional but recommended:* attach Postgres (Vercel Postgres/Neon) so question logs & callback leads persist:
   - set `DATABASE_URL` (pooled URL), then from your machine:
     `npx drizzle-kit push` — creates `chat_logs` and `leads`.
   - Without it the assistant still answers and hands off normally; logging is skipped silently.

## Updating the knowledge base (the important part)

The content comes only from `content/*.md` — compiled here from yes.edu.in's public pages. To make it the
college's own: drop the registrar's converted pages/brochure in as `.md` files (frontmatter: `title`,
`programme`, `source_url`), then:

```bash
node scripts/ingest.js && node scripts/selftest.mjs
git add content data && git commit -m "content update" && git push   # Vercel redeploys
```

## Test on a phone (checklist for the demo day)

- [ ] Open the site on 4G — first paint in ~2–3 s; disclaimer strip readable.
- [ ] Orange button bottom-right → chat opens **full-screen**; tap targets are thumb-sized.
- [ ] Tap each quick chip once — answers come back in ~2–4 s, with a "From: …" source line.
- [ ] Switch **EN → हिं → मराठी** — UI text changes; ask a question in each language, reply follows the language.
- [ ] Ask **"फी किती आहे?"** — assistant explains FRA fees and gives the official fee page, **never a number**.
- [ ] Ask something outside admissions (e.g. "write python code") → polite decline, stays in persona.
- [ ] Ask an unanswerable detail (e.g. tomorrow's couselling time) → **no LLM guess**: WhatsApp button with the
      chat summary prefilled to the college number; opening it lands in the college's own WhatsApp.
- [ ] Voice: mic on Chrome/Android (hi-IN/mr-IN) transcribes and sends; on iOS Safari the fallback message shows.
- [ ] Submit the callback form without consent → blocked; with consent → saved; lead appears (masked) in /admin's live strip.
- [ ] /admin clearly reads **SAMPLE**; the green live strip shows your own questions with language & score.
- [ ] Fire 20+ messages quickly → rate-limited message, not a crash.
- [ ] Rotate the phone / press back — no layout breakage; ESC closes on desktop.
- [ ] Toggle airplane mode mid-send → graceful error message + WhatsApp fallback still offered.

## Security notes

- `OPENROUTER_API_KEY` is read **only** server-side (`/api/chat`); nothing is shipped to the browser.
- Fixed system prompt; user text and retrieved text are wrapped as data; answers get a final scrub for banned
  claims. 500-char cap and per-IP rate limits on both endpoints. Phones are masked in admin output; IPs are
  hashed before logging.
